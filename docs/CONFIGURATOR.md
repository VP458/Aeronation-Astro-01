# Recon configurator — architecture and handover notes

## Phase 0 outcome (why Path B)

Per the build brief, no application code was written until the geometry
question was settled:

| Checked | Result |
|---|---|
| Repo + full git history (`.glb .gltf .obj .fbx .step .stp .blend`) | none |
| Google Drive (search across all accessible files for 3D formats) | none |
| Cloudflare R2 | **unverified** — the build session had no `CLOUDFLARE_API_TOKEN`; run `wrangler r2 bucket list` locally to close this out |

→ **Path B: pre-rendered turntable configurator.** The interactive shell,
state model, option schema and URL deep-linking are all real and final;
only the frame sequences behind them are placeholders.

## Architecture

- **State model** (`src/configurator/types.ts`) — renderer-agnostic
  `ConfigState` + `TurntableViewer` interface. Path A (Three.js) would
  implement the same interface; nothing above the viewer changes.
- **Option schema** (`src/config/options.ts`) — single source of truth,
  grounded in programme material where possible (see
  `docs/spec-sources.md`), `placeholder: true` on everything unsourced.
- **Viewer** (`src/configurator/viewer.ts`, `loader.ts`) — canvas 2D frame
  scrubber: drag / arrow keys, inertia, adjacent-frame preload,
  `createImageBitmap` decode off the main thread, low-res-first upgrade,
  auto-rotate that stops on first interaction, `prefers-reduced-motion`
  honoured. Canvas 2D was chosen over WebGL deliberately: it *is* the
  degradation path the quality floor demands, and it hits 60fps for frame
  blitting on any device that can decode WebP.
- **Deep links** (`src/configurator/url-state.ts`) — every configuration
  serialises to the query string (`?colourway=…&payload=…&endurance=…&az=…`)
  so sales can send a specific build.
- **Page** (`src/pages/index.astro`) — instrument-panel UI; the D1 demo
  that previously lived at `/` moved to `/demo`.

## Frame sequences

Layout: `public/frames/{colourway}/{payload}/{endurance}/{size}/{nnn}.webp`
described by `public/frames/manifest.json` (`FramesManifest`).

The shipped sequences are **schematic wireframe placeholders** generated by
`npm run frames:placeholder` — deliberately drawn as a technical schematic
(the brief forbids toy-like photoreal reconstructions), watermarked
"PLACEHOLDER SEQUENCE" in every frame and flagged in the manifest, the HUD
and the panel note.

### Swapping in real renders (when geometry or a render pipeline lands)

1. Render 36 (or 72) azimuth frames per option combination out of
   Blender/KeyShot — camera elevation ~18°, transparent background,
   lighting matched to `Reconnaitre-Product-Drone-Full-Width.png` so the
   configurator sits coherently next to the existing hero.
2. Export AVIF + WebP at 1280 and 640 widths into the same directory
   layout; add `"avif"` before `"webp"` in `manifest.formats`, set
   `"placeholder": false`, bump `frameCount` if 72.
3. Delete `scripts/generate-placeholder-frames.mjs` usage from the build
   docs. Nothing else changes — the viewer reads the manifest.

### Swapping in real-time 3D (Path A)

Implement `TurntableViewer` over a Three.js scene (ACES Filmic, IBL HDRI,
KTX2/Draco assets) in a new `src/configurator/viewer-webgl.ts`; feature-test
WebGL2 at boot and fall back to the frame-sequence viewer. The page, state,
options and URL code are untouched.

## Data honesty

- Spec readouts render **amber** when the figure is a placeholder and
  phosphor-green only when sourced (currently: MTOW ≤7 kg and the 422 Wh
  standard pack are sourced; endurance/range are placeholder formulas).
- The masthead shows **UNVERIFIED DATA** while any option carries
  `placeholder: true`.
- What is needed to clear the flags is listed in `docs/spec-sources.md`
  ("Gaps") — chiefly: Recon-specific endurance/cruise/range figures, the
  real microsite calculator formulas, confirmed colourways, and whether an
  extended energy fit exists at all.
